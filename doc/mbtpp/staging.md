# MoonBit++ 分阶段元编程

参考：MetaOCaml（Kiselyov, FLOPS 2014）的引用与拼接；MacoCaml（Xie 等, ICFP 2023）的编译期拼接；
Kovács, *Staged Compilation with Two-Level Type Theory*（ICFP 2022）把分阶段看作求值。文献见
[references.md](references.md)。

## 0. 总体

| 项目 | 决定 |
| --- | --- |
| 类型 | `Code[T]`：类型为 `T` 的代码；`Code[T raise E]`、`Code[T!Eff]`：运行时有效应的代码 |
| 引用 | `code { e }`：`e` 的代码（`code` 不是关键字，后面紧跟 `{` 时才是引用） |
| 拼接 | `${ c }`、`$x`：把代码 `c` 放在这里 |
| 运行 | `c.run()`：在运行时运行代码 |
| 阶段 | `code { }` 加一，`${ }` 减一；声明在阶段 0；变量不能在比绑定处更低的阶段使用 |
| 编译期 | 声明里阶段 0 的拼接在检查程序时运行，并被它生成的代码替换 |
| 语义 | 去掉阶段标注后的程序（`${ code { e } }` 就是 `e`）；检查器按这个语义计算 |
| 拼接的效应 | 不依赖所在代码的变量的拼接，在代码生成时运行，效应属于生成器；其余拼接必须是纯的 |
| 运行时 | 代码是闭包；解释器和编译器都不需要求值器 |
| 生成器里的状态 | 数组是真的可变值，`print` 在检查时输出；导入的 MoonBit 函数由 moonpp 构建的驱动程序运行（第 6 节） |
| 不做 | 对代码做模式匹配（`Code` 是抽象的） |

## 1. 动机

依赖类型较重的代码（类型层计算、GADT 细化、高阶 trait）在编译时退化为统一的值表示，比原生
MoonBit 代码慢。分阶段把这类计算放到生成器里：生成器在检查程序时运行，留下的是一阶代码，能进入
[原生片段](../../book/src/interop/compile.md)。典型的例子：

```moonbit
fn power(n : Nat, x : Code[Int]) -> Code[Int] {
  match n {
    Z => code { 1 }
    S(k) => code { ${x} * ${power(k, x)} }
  }
}

fn cube(x : Int) -> Int {
  ${ power(3, code { x }) }       // 检查后：x * (x * (x * 1))
}

lemma cube_2 : cube(2) === 8 = Refl
```

`README` 里的 `Exp[T]` 求值器分阶段之后就是编译器（Pašalić、Taha、Sheard, ICFP 2002），见
[examples/staging.mbtpp](../../examples/staging.mbtpp)。

## 2. 阶段

每个变量有绑定它的阶段。`code { e }` 中 `e` 的阶段比外面高一，`${ c }` 中 `c` 的阶段比外面低一。

- 在更高的阶段使用变量总是可以的：生成代码时它的值已经知道，值被放进代码里（跨阶段持久化）。
  值是数、字符串、构造子、函数、类型、trait 实例都可以，不需要 `Lift` 之类的 trait。
- 在更低的阶段使用变量是错误：`fn f(x : Int) -> Int { ${ g(x) } }` 中，`x` 要到运行时才知道。
  类型和证明例外：它们会被擦除，任何阶段都可以用。
- `let mut` 变量不能跨阶段使用（生成的代码无法与生成器共享变量）；先 `let x0 = x`。

阶段只用来保证“阶段 0 的拼接可以在检查时运行”。程序的含义与阶段无关。

## 3. 语义

`Code[T]` 的值是一段等待运行的代码。去掉 `code { }` 和 `${ }`，程序的结果不变——这是分阶段程序
的擦除性质（Inoue、Taha, ESOP 2012），这里把它当作定义：

- 检查器把 `code { e }` 当作值，`${ c }` 和 `c.run()` 在 `c` 已知时就是它的内容。所以
  `cube(2) === 8` 用 `Refl` 证明，`inc(c).run() === c.run() + 1` 也可以。
- 两段代码在内容相同时相等；`code { ${c} }` 与 `c` 相等。
- 拼接的位置不参与比较。

### 拼接什么时候运行

和 MetaOCaml 一样，`code { … ${a} … }` 中的 `a` 在 `code { … }` 被求值时运行，不是在代码被运行时。
实现上，声明的定义体（已经没有元变量）经过一遍变换，把每个引用里**不依赖引用内部变量**的拼接
提前：

```text
code { … ${a} … ${b} … }
  ⇒  %quote({ let s0 = a; let s1 = b; j => match j { 0 => s0; 1 => s1 } },
            env => … ${env(0)} … ${env(1)} …)
```

因此：

- `a` 中的 `raise` 和效应属于生成器（生成 `code { }` 的函数），由它的调用者处理。检查时，这样的
  拼接在引用所在的上下文里检查（允许那里的效应）。
- 生成器做的计算（`power` 对 `n` 的递归）只在生成代码时做一次，运行代码时不重复。运行时的
  `Code` 因此是真正分阶段的，不是简单的延迟求值。
- 依赖引用内部变量的拼接（例如 `code { (y : Int) => ${ f(code { y }) } }`）只能和代码一起运行，
  所以要求它是纯的：不能 `raise`，不能执行效应。报错会说明原因。
- 效应多态的推导相应调整：函数参数只在拼接里被调用时，仍然可以推导出 `!e`；它被引用捕获，或
  在拿到代码的拼接里被调用时，按逃逸处理（即要求纯）。

## 4. 编译期展开

检查完一个包之后，对每个定义体做一次展开（`unstage_all`）：

- 阶段 0 的拼接 `${ c }` 被求值（用检查器的求值器，包括检查期执行可变状态函数的部分），得到一段
  代码；把这段代码的定义体原样取出，其中的变量换成它们的值，其中的拼接继续展开。
- 生成器知道的值重新变成项：生成代码里的变量是它自己，函数和代码按写法保留（循环、赋值等不被
  计算），大的自然数仍是字面量。
- `return` 只离开代码本身：含 `return` 的代码被展开成一次函数调用。
- 类型和隐式参数里的拼接不展开（它们被擦除）。
- 展开期间 `#opaque` 不起作用（它只关乎类型检查）；`#timelimit` 照常生效。
- 拼接里的代码是检查时算不出来的（卡在数组、`print`、导入的函数上），报错并显示卡住的项。

展开之后，解释器、擦除分析和编译器看到的是普通的核心项。只被生成器用到的函数不可达，不会被
编译。

### 生成代码里的局部递归函数

核心语言没有局部递归，局部递归函数被提升为全局函数，以所在上下文的变量为参数。引用里的局部
递归函数在展开时被特化：对上下文中已知的值生成一个新的全局函数 `f$go$N$sM`，参数是它用到的
生成代码的变量（类型已知时带类型，否则是 `%Any`），递归调用指向自己。特化正在进行时遇到的
另一个局部函数不再特化，它的调用保持原样（在运行时运行自己的拼接）。

## 5. 运行时

没有被展开的引用（生成器函数本身、`run`）编译为闭包：

- `%quote(s, f)`：先求值 `s`（拼接的结果），得到 `() => f(s)`；
- `${ c }`、`c.run()`：调用它。

解释器和统一表示的代码生成各加三个原语。`Code[T]` 不是原生类型，使用它的函数按统一表示编译。

## 6. 生成器里的数组、`print` 与 MoonBit 函数

展开拼接时（`unfold_everything`）求值器像程序一样运行：

- 数组字面量每次求值产生一个新数组，`%array_*` 原语在饱和时直接操作它（`run_prim`）；`print`
  追加到 `staging_output`（并输出）。语句的值（`Seq`、`let`）在这时被强制，调用按顺序发生；调用得到
  的错误变成 `Thrown`，被生成器的 `try` 捕获。
- 数组是值：`exec_call` 不再因为结果是数组而让调用保持折叠；放进代码时（`reify`）数组变成字面量。

导入的 MoonBit 函数检查器没有定义。`FfiHost`（`src/tt/ffi.mbt`）是它与能运行 MoonBit 的一方之间的
接口：`prepare(names)` 让这些函数可以调用，`call(name, args)` 调用，`set_callback` 给对方一个运行
检查器的函数的入口。moonpp（JS 版）实现它（`src/moonpp/driver.mbt`）：

1. 找出拼接可能调用的导入函数（从有拼接的定义能到达的 `@mbt:` 原语）；
2. `@codegen.generate_driver` 生成一个 MoonBit 程序：这些函数的 FFI 包装（编译器用的那些，`ffi_fn`）、
   运行时、和 `call`（`mbtpp_driver.mbt`）；
3. 写成 `mbtpp_out/driver` 项目，`moon build --target js`，用 `require` 加载到 moonpp 进程里；
4. 检查器把参数写成文本，调用 `call`，按函数的结果类型读回结果。

值的文本（`src/tt/ffi.mbt` 与 `src/codegen/driver.mbt` 各有一份读写）：`u` 单位、`b0`/`b1`、`i<n>;`
（`Int`）、`L`、`U`、`V`、`y`、`c`、`d`/`f`（浮点的位）、`n<数字>;`（`Nat`、`BigInt`）、`s<k>:`加 k 个字符
（字符串）、`a<k>;` 加 k 个值（数组）、`k<m>:`构造子名`<k>;`加 k 个字段（数据类型）、`h<id>;`（MoonBit
一侧保存的值）、`F<id>;<k>;`（检查器的函数，MoonBit 回调它）。构造子由运行时的 `con_makers` 按名字
重建；结果的参数从函数的结果类型取。用自己的文本格式而不用 JSON，是为了不依赖核心库的 JSON API。

驱动在进程内（JS 模块），同步调用，所以 MoonBit 保存的值（句柄）在多次调用之间保留，回调可以重入
检查器。

## 7. 实现

- 语法：`code { e }` 解析为 `%quote(() => e)`，`${ e }` 解析为 `%splice(e)`；没有新的表面语法
  结点，也没有新的核心项结点。类型实参可以带效应（`Code[T raise E]`）。
- `src/tt/staging.mbt`：原语、阶段（上下文里的 `stage`、`stage_marks`、`quote_cxt`）、引用与
  拼接的精化、拼接提前（`hoist_splices`，在 `set_body` 中）、展开（`expand`、`reify`、
  `specialize`）。
- 求值与合一：`%splice`/`%run` 遇到 `%quote` 时归约；引用是值（不阻塞函数的展开）；合一的
  η 规则；`may_raise` 认识可能抛错的拼接；检查期执行不把引用的内容当作副作用。
- 打印：`code { }`、`${ }` 和语句（`let mut`、赋值、循环等），用于报错和展开结果。

## 8. 限制

- 导入的 MoonBit 函数只能在 moonpp 里调用（要有 `moon`，导入的包要能编译到 JS）；playground 和
  `moonpp ide` 里这样的拼接算不出来（编辑器里会报错）。
- 调用在求值到它时发生：有副作用的 MoonBit 函数要写成语句；被折叠的纯函数调用可能被求值多次。
- 值的类型要能被编译器的 FFI 转换；有被擦除字段的数据类型不能传。
- 依赖生成代码变量的拼接必须是纯的；所以用 `ctl` 效应做 let 插入（在生成的绑定下恢复）不行，
  用延续传递的写法可以（见测试 `generators with mutable state, and let insertion`）。
- 不能检查代码的结构。
- 生成代码里嵌套的局部递归函数不特化。
- 没有终止检查：不终止的生成器会让检查超时。
